# Backend Architect Delivery Checklist

## 接口设计

- 是否明确列出了新增或修改的 API 路径、方法和用途
- 请求参数、响应结构和错误返回是否清晰
- 是否避免接口语义模糊或字段命名不一致

## 服务与数据模型

- 是否说明了 `main.py` 和 `service.py` 的职责分配
- 是否明确数据表、记录结构或统计逻辑的改动点
- 是否考虑兼容已有数据与历史行为

## 边界与安全

- 是否有输入校验和必要的默认值处理
- 是否考虑多用户隔离、空数据和非法参数场景
- 是否避免明显的注入、越权或脆弱时间逻辑问题

## 测试与回归

- 是否补齐了对应的 `tests/unit` 测试
- 如涉及端到端流程，是否补充 `tests/integration` 验证
- 是否说明了对现有功能的回归风险

## 工程化一致性

- 是否与现有 `pytest`、`flake8`、`black` 约束兼容
- 是否避免引入难以维护的耦合逻辑
- 是否记录了后续可能的重构点或技术债
