# Agents

本目录用于沉淀项目内可复用的智能体角色定义，方便在后续需求开发中快速指定分工、统一输出风格，并减少重复描述上下文的成本。

## 当前可用角色

- `frontend-architect`
  - 聚焦前端页面、组件结构、交互体验、状态管理、样式一致性与前端测试建议。
- `backend-architect`
  - 聚焦 API 设计、业务服务、数据结构、数据库演进、测试策略与后端质量保障。

## 目录规范

每个 agent 目录建议包含以下内容：

- `README.md`
  - 角色定位、职责范围、协作边界、输出要求。
- `openai.yaml`
  - 对接工具或平台时可复用的显示名称、简介与默认提示词。
- `prompts/`
  - 常见任务场景下的提示词模板，帮助快速启动一次协作。
- `checklists/`
  - 交付前的自检清单，降低遗漏接口、测试、边界条件的风险。
- `examples/`
  - 可选。记录真实任务示例、典型输入和理想输出风格。

当前仓库先落地 `README.md`、`openai.yaml`、`prompts/` 和 `checklists/`。

## 建议使用方式

1. 先明确任务范围，再选择对应角色。
2. 单一职责优先，避免一个角色同时承担前后端全部工作。
3. 复杂需求优先拆分为前端、后端、集成、测试四类任务。
4. 角色产出后，由主线程统一集成、复核与回归验证。
5. 对较大需求，优先复用各角色目录下的 `prompts/` 模板。
6. 合并前至少过一遍对应 `checklists/` 自检清单。

## 与 `skills/` 的区别

- `agents/`：更偏角色定义与协作分工，用于明确“谁负责什么”。
- `skills/`：更偏能力模板与操作方法，用于明确“如何做某类事”。

## 当前项目中的典型应用

- 工位打卡页：前端角色负责页面结构与交互，后端角色负责记录接口与服务逻辑。
- 番茄钟工作法：前端角色负责计时器体验与状态切换，后端角色负责番茄会话记录与统计接口。

## 推荐协作流程

1. 主线程整理需求背景、当前文件范围和约束条件。
2. `backend-architect` 先明确 API 契约、数据结构和测试范围。
3. `frontend-architect` 基于接口契约设计页面与交互流程。
4. 双方对齐字段命名、错误场景和空态展示。
5. 主线程集成代码后，统一执行测试和回归验证。
